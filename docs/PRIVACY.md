# 公开版本的数据与隐私边界

## 允许进入公开仓库的内容

源代码、通用部署模板、合成测试数据和自行编写的架构说明。
不要提交客户聊天/导出表、数据库快照、知识库原文/索引、会议纪要、内部规划、
真实企业/成员标识、生产地址、域名验证文件、访问令牌、模型密钥或私钥。

忽略规则不是安全边界：已跟踪文件不受 `.gitignore` 保护，新增文件仍须人工审阅，
提交及历史中的凭据由 CI 密钥扫描辅助检查。

## 部署者需要落实的约束

- 会话存档应在平台授权范围内启用，并依法完成相应告知与同意；代码不会替部署者取得授权。
- 原始消息目前没有自动过期删除任务。部署者须结合处理目的制定保存期限、删除/导出流程与访问审计，不能把技术上的长期保存视为无限期保存的授权。
- 摘要、回复生成及候选提炼可能把会话片段发送给配置的模型服务；先核验供应商、数据处理条款、地域与最小必要字段。
- 用户身份、客户消息、提示词和知识库正文不能进入公开日志、截图或简历演示；演示使用合成数据。
- 管理后台仅配置需要的账号与角色；限制公网登录，配置 HTTPS、限流、防火墙、备份加密及最小权限数据库账号。
- 只读知识服务与向量服务只应运行在回环/隔离网络，不直接暴露公网；知识服务 Token 仅配置授权库的最小权限。
- 若曾提交真实凭据，应先在服务端撤销/轮换。删除 Git 历史不能使已泄露凭据失效，也不能删除他人克隆或平台缓存。

## 授权与展示边界

维护者已确认取得公司对代码展示与开源的授权；该授权不扩大到企业隐私资料。
公开版本不包含授权文件原件、签字、员工身份或公司联系人信息。
简历应如实区分上游代码、本人实现与团队协作，不附真实客户数据或未验证的业务指标。
